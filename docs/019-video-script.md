# 019 发布视频脚本（3–5 分钟）

> 目标：让第一次看到项目的人在 4 分钟内明白「这是什么、怎么装、装完怎么用、和上游什么关系」。
> 全片口播约 900–1100 字，按 4 分钟计。括号内是操作与画面提示，不是念出来的内容。
>
> **2026-11-07：桌面外壳已移除。** 本稿是按 0.1.0 的桌面应用写的**历史脚本**，其中「双击打开/快捷方式/实例窗口/`instances.ps1`」等镜头已无对象，不能再按原样录制；附表第 7 行与 3:00–3:30 分镜已标注作废。当前插件路线的演示稿尚未重写。

## 录制前准备（清单）

1. 一台**干净**的 Windows 机器或一个干净用户目录（体现"一条命令装好插件"；原外壳的"一行安装"已随外壳移除）。
2. 演示仓库：一个公开的 playground 仓库；准备**第二个 GitHub 账号**用来发触发（智能体账号不能自己触发自己）。
3. 两处窗口预先排好：桌面（显示快捷方式）与浏览器（Release 页、playground 的 issue）。
4. 应用已卸载或未启动；录屏区域 1920×1080，系统缩放 100%。
5. 关掉通知；把 `%APPDATA%\Superagent\app.log` 所在文件夹先在资源管理器里打开一份备用。

## 分镜

### 0:00–0:20 标题与定位

（画面：DSH-Superagent 窗口 + 桌面快捷方式，缓慢推近；右下角常驻一行小字：
`Windows deep adaptation of the DeepSeek team's SuperAgent for DSH · MIT © 2026 DeepSeek Harness Team`）

> 这是 DSH-Superagent，DeepSeek 团队最新的 SuperAgent 在 DSH 工具里的 Windows 深度适配版。
> 它把官方原型做成能双击打开的应用，并补上了官方文章里描述、原型还没实现的部分。
> 先说清楚：这是**非官方**项目，上游是 DeepSeek 官方的 dsh-superagent-prototype，MIT 许可，版权归原作者。

### 0:20–0:50 它是什么（不用术语）

（画面：切换到面板「介绍」页，跟着念到的区块高亮：这个面板是什么 / 一条请求的路径 / 各页面在做什么）

> 一句话：它是一台持续在线的开发助手。你或同事在 GitHub 上提一个请求，它自己判断值不值得做，
> 值得就开单、在自己的会话里干活，做完把结果贴回原处——评论或者一个 Pull Request。
> 它不占用你的对话窗口，也不要求你逐个盯进度：面板就是它的控制台。

### 0:50–1:30 安装（重点：一条命令）

（画面：桌面 → 打开 PowerShell（无管理员）→ 粘贴安装命令 → 回车。
录屏时把下载进度、`checksum OK`、`Installing…`、`Done` 四行放大。桌上出现新快捷方式后双击启动。）

> 安装只有一条命令：`irm` 加仓库地址，管道给 `iex`。它会下载最新发布包、**校验 SHA-256**、解压，
> 再跑包里的安装器。不需要装 Python、不需要 tmux、不需要另外起 Web 服务——git、gh、PowerShell 7 都在包里。
> 网络访问不了 github.com 的 releases，它还会自动改走 API 下载同一个文件。

（画面：启动画面 → 主界面出现，点「打开主 Session」再关掉，展示它是完整应用）

### 1:30–2:20 面板五个页面（第一次使用）

（画面：依次点开 概览 → 来源 → 触发 → 评估 → 执行 → 设置，每页停 2 秒，鼠标指向关键数字）

> 面板有六页，第一次用只要记住四件事。**来源**：现在监听哪个仓库、账号是否在线。
> **触发**：环境里发生过什么、哪些被程序层直接过滤掉、为什么。
> **评估**：需要语义判断的候选，接单、忽略还是来问你。**执行**：正在跑和排队的工单，以及每个工单的会话与报告。
> 右上角「打开主 Session」可以像平常一样直接跟它说话。

### 2:20–3:00 一次真实触发（第二个账号）

（画面：浏览器里用第二个账号在 issue 下留一条**不带 @** 的评论 → 切回面板 →
「触发」页出现新行、状态变化 → 「评估」页出现判断 → 「执行」页出现工单）

> 现在演示一次真实触发。我们用第二个账号留一条评论——不带 @，因为点名会走另一条快速通道。
> 几十秒内，触发出现在面板里，被判断为候选；语义层给出结论；接单后工单出现在执行页，会话开始干活。
> 全程没有人敲一句命令。

### 3:00–3:30 多实例（一个边界一个实例）

（画面：~~运行 `instances.ps1 -Action list` → 打开应用「文件 → 实例…」→ 点"打开"弹出第二个窗口，标题不同~~ **已作废：外壳已移除**；改用 CLI 起第二实例的画面）

> 一个进程只服务一个上下文边界。另一个团队、另一个仓库，就再起一个实例：各有自己的状态目录、配置和凭据。
> 这一条是官方设计里的原则，不是我们发明的。

### 3:30–4:00 后台的两件「上游没做」的事

（画面：设置 → 执行 → 控制回路（Watchdog）与 Router 分片；指到四个输入框；然后切到日志/健康项）

> 两个默认关闭、但可在这里调的东西。**Watchdog**：定时唤醒一个独立会话，看工单是不是真的在推进；
> 健康且没变化时它不会唤醒模型，所以基本不花钱；停滞的工单会被标出来。
> **Router 分片**：按 Thread 稳定分配，同一个对话不会被两个记忆分别处理。默认 1，即不启用。

### 4:00–4:30 与上游的关系（必须保留）

（画面：GitHub 的 README 顶部与 NOTICE、docs/WINDOWS-DELTA.md；镜头停在「上游」链接与 MIT 版权行）

> 最后说清楚关系：上游是 DeepSeek 官方的 dsh-superagent-prototype，MIT，版权归 DeepSeek Harness Team。
> 我们做的这一层——桌面应用、多实例、Watchdog、分片、文档与测试——同样以 MIT 发布，
> 每一项差异都记在 WINDOWS-DELTA 里；上游哪天实现了同样的机制，我们就删掉自己的版本切回上游。
> 链接都写在 README 和 NOTICE 里。

### 4:30–4:40 收尾

（画面：回到面板概览，鼠标停在「介绍」标签；右下角字幕：仓库地址 + Releases 地址）

> 这就是 DSH-Superagent。安装命令、文档和归属说明都在仓库里，第一个标签就是给你看的介绍。

## 录制与剪辑提示

1. **先录 B-roll**：面板各页、启动画面、快捷方式、Release 页；再录操作，剪辑时穿插。
2. 关键命令与校验行**放大 120%**，停留 ≥2 秒；观众会暂停看。
3. 任何「删掉仓库/删数据」的镜头都不要出现；演示只用 playground 仓库。
4. 字幕：中文旁白配**中文硬字幕**；片尾固定一帧，含仓库地址、Release 地址与上游地址。
5. 片头与片尾必须出现归属行：
   `Upstream: deepseek-ai/dsh-superagent-prototype · MIT · © 2026 DeepSeek Harness Team`。
